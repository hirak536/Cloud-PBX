# Client API & Webhook Integration

This document describes the Client API and webhook system for server-to-server integration with the PBX platform.

---

## Overview

- Tenant-scoped APIs authenticated via **API Key**
- Tenant list accessible via **Master Key** (not tenant-scoped)
- Webhooks notify your server of changes in real time
- All webhook payloads are optionally signed with HMAC-SHA256

---

## Authentication

### API Key (Tenant-Scoped)
Used for all tenant data endpoints (extensions, DIDs, CDR, fax, voicemail).
```
Authorization: ApiKey <your-api-key>
```
Generated by the PBX admin per tenant. Shown once on creation (also delivered via `key.generated` webhook).

### Master Key (Tenant List Only)
Used only for `GET /api/v1/client/tenants/`.
```
Authorization: MasterKey <your-master-key>
```
Generated by the PBX admin in Django Admin. Only one master key exists. Only allows listing tenants — cannot access tenant data.

---

## Setup (One Time)

| What | Who Provides |
|------|-------------|
| `webhook_url` | Other server |
| `webhook_secret` | Agreed between both sides |
| `api_key` | PBX admin — delivered via `key.generated` webhook |
| `master_key` | PBX admin — shown once in Django Admin |

## API Endpoints

Base URL: `https://yourserver.com/api/v1/client/`

---

### Tenant List *(Master Key only)*

```
GET /api/v1/client/tenants/
Authorization: MasterKey <master-key>
```
Response:
```json
[
  {
    "tenant_id": "92b3e21f-b14b-49b0-8b4c-fd40c928dfca",
    "tenant_code": "DEMO",
    "tenant_name": "Cloud Communications Solutions"
  }
]
```

### Get My Tenant Info *(API Key)*

```
GET /api/v1/client/tenant/
Authorization: ApiKey <api-key>
```
Response:
```json
{
  "tenant_id": "92b3e21f-b14b-49b0-8b4c-fd40c928dfca",
  "tenant_code": "DEMO",
  "tenant_name": "Cloud Communications Solutions"
}
```
Use the returned `tenant_id` as the `{tenant_uuid}` in all subsequent URLs.

### CDRs

#### List Call Records
```
GET /api/v1/client/{tenant_uuid}/cdr/
```
Response:
```json
{
  "count": 1500,
  "page": 1,
  "page_size": 25,
  "results": [
    {
      "xml_cdr_uuid": "uuid",
      "caller_id_number": "+12293025400",
      "caller_id_name": "John Smith",
      "destination_number": "901",
      "direction": "inbound",
      "start_stamp": "2026-03-27T10:00:00Z",
      "answer_stamp": "2026-03-27T10:00:05Z",
      "end_stamp": "2026-03-27T10:05:00Z",
      "duration": 300,
      "billsec": 295,
      "hangup_cause": "NORMAL_CLEARING",
      "missed_call": false,
      "record_path": null
    }
  ]
}
```

**Supported Filters:**
| Parameter | Example | Description |
|-----------|---------|-------------|
| `direction` | `?direction=inbound` | inbound / outbound / local |
| `start_stamp__gte` | `?start_stamp__gte=2026-03-01` | From date |
| `start_stamp__lte` | `?start_stamp__lte=2026-03-31` | To date |
| `hangup_cause` | `?hangup_cause=NO_ANSWER` | Hangup reason |
| `missed_call` | `?missed_call=true` | Missed calls only |
| `search` | `?search=9015551234` | Search caller/destination |
| `page` | `?page=2` | Page number |
| `page_size` | `?page_size=50` | Results per page (max 100) |

#### Get CDR Detail

## Webhooks

Webhook events are fired to the `webhook_url` configured on the API key.

### Payload Structure

#### Standard Events (extension, DID)
```json
{
  "event": "extension.updated",
  "tenant_code": "DEMO",
  "tenant_id": "uuid",
  "object_id": "uuid-of-changed-object",
  "timestamp": "2026-03-27T10:00:00Z"
}
```

#### Key Events
The `key.generated` event includes the plaintext API key — store it securely, shown only once:
```json
{
  "event": "key.generated",
  "tenant_code": "DEMO",
  "tenant_id": "uuid",
  "object_id": "uuid-of-api-key",
  "timestamp": "2026-03-27T10:00:00Z",
  "data": {
    "api_key": "plaintext-api-key-shown-once"
  }
}
```
The `key.revoked` event has no `data` field — stop using the key immediately.

#### Real-Time Events

**Incoming Call:**
```json
{
  "event": "call.incoming",
  "tenant_code": "DEMO",
  "tenant_id": "uuid",
  "object_id": "call-uuid",
  "timestamp": "2026-03-27T10:00:00Z",
  "data": {
    "caller_id_number": "+12293025400",
    "caller_id_name": "John Smith",
    "did_number": "+18332715337",
    "destination_extension": "901",
    "destination_name": "John Doe"
  }
}
```

**New Voicemail:**
```json
{
  "event": "voicemail.received",
  "tenant_code": "DEMO",
  "tenant_id": "uuid",
  "object_id": "message-uuid",
  "timestamp": "2026-03-27T10:00:00Z",
  "data": {
    "caller_id_number": "+12293025400",
    "caller_id_name": "John Smith",
    "voicemail_id": "901",
    "duration_seconds": 45
  }
}
```

### Webhook Signature

If `webhook_secret` is configured, every request includes:
```
X-Signature: <hmac_sha256_hex(raw_body, webhook_secret)>
```
Verify on your server:
```python
import hmac, hashlib
expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
assert hmac.compare_digest(expected, request.headers['X-Signature'])
```

### Events Reference

| Event | Trigger | Data Included | Recommended Action |
|-------|---------|---------------|--------------------|
| `extension.created` | New extension added | No | Fetch `GET /{tenant_uuid}/extensions/{object_id}/` |
| `extension.updated` | Extension modified | No | Fetch `GET /{tenant_uuid}/extensions/{object_id}/` |
| `extension.deleted` | Extension removed | No | Delete locally |
| `did.created` | New DID added | No | Fetch `GET /{tenant_uuid}/destinations/{object_id}/` |
| `did.updated` | DID modified | No | Fetch `GET /{tenant_uuid}/destinations/{object_id}/` |
| `did.deleted` | DID removed | No | Delete locally |
| `key.generated` | New API key created | **Yes** (`data.api_key`) | Store key from `data.api_key` |
| `key.revoked` | API key disabled | No | Stop using key immediately |
| `call.incoming` | Inbound call arrives | **Yes** | Push notification to user |
| `voicemail.received` | New voicemail left | **Yes** | Push notification to user |

### Delivery & Retry

```
Webhook sent → HTTP < 300            → success
Webhook sent → HTTP >= 300 or timeout → retry after 30s
After 3 failures                     → marked failed, logged
```

---

## Key Lifecycle

```
PBX admin creates API key with webhook_url configured
       ↓
key.generated webhook fired → other server receives key in data.api_key
       ↓
Other server stores key and uses it for all tenant-scoped API calls
       ↓
Key rotated (on demand)
       ↓
key.revoked webhook fired → other server stops using old key
key.generated webhook fired → other server receives new key in data.api_key
```

## Error Responses

| Status | Meaning |
|--------|---------|
| `401` | Invalid or missing API key / Master key |
| `403` | Valid key but tenant UUID mismatch |
| `400` | Missing required parameter |
| `404` | Object not found |
